### Component Session Rules

- Every component session must change real CSS, raw docs/examples, or validation tooling, unless the row is explicitly deferred with release impact.
- Every breaking selector, import, token, or copyable docs-example change requires migration notes before `REL-S03`.
- Consumer-owned JavaScript, keyboard behavior, ARIA synchronization, validation, routing, lifecycle, focus, and live-region behavior must be named in docs.
- Source CSS is the current behavior truth; raw docs and archived audit files are evidence when planning fixes.

## 1.0.0 Acceptance Gates

- Active planning remains compact and session-based.
- Every component CSS file plus `src/identity.css` is covered by a component session.
- Priority docs are rewritten and examples are copy-safe.
- Infrastructure can verify CSS, docs, generated metadata, package paths, `dist`, themes, accessibility, responsive behavior, and publish readiness.
- Every breaking change has migration notes before `REL-S03`.

## Stop Conditions

Stop the release until resolved if any of these are true:

- `dist` cannot be reproduced from source.
- package import smoke tests fail.
- docs metadata cannot be regenerated or verified.
- component examples use missing selectors or inaccessible controls.
- breaking changes lack migration notes.
- release workflow cannot prove the package that will be published.
