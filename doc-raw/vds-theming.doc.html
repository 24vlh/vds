Shared guidance

Theming

VDS themes are separate package-facing CSS files. Components consume tokens; applications choose the active theme, validate contrast, and decide whether custom token overrides are allowed.

Source truth

Theme imports

Theme source lives under src/themes/. Package consumers load theme files from dist/themes/ separately from the component bundle. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/vds.css";
@import "@24vlh/vds/dist/themes/graphite.css";

Example

Token override boundary

Prefer official theme files. If a product layer overrides tokens, it owns contrast and regression testing for every component using those tokens. 

:root[data-theme="product-light"] {
  --color-bg: #ffffff;
  --color-text: #162033;
  --color-accent: #2854c5;
}

A custom theme must be checked against components, utility classes, focus rings, semantic states, reduced-motion behavior, and forced-colors fallbacks.

Accessibility

Contrast, motion, and forced-colors

CSS contains tokenized styles and some forced-colors/reduced-motion hooks, but final readability depends on the theme and the consuming layout.

  • Do not rely on color alone for success, warning, danger, current, or selected meaning.
  • Validate focus-visible indicators in every shipped theme.
  • Respect user motion preferences and avoid adding app-level motion that bypasses VDS CSS.
  • Document custom token overrides in migration and release notes.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
