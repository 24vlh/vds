Docs foundation

Documentation Blocks

Doc blocks provide structured documentation surfaces for sections, previews, code blocks, toolbars, collapsed code, notes, highlights, and diff-like examples.

Source truth

Imports and root aliases

Doc blocks are authored in src/components/doc-block.css and ship through dist/components/doc-block.css. The corrected root aliases are data-vds-doc-block and vds-doc-block; old dock-block aliases remain compatibility hooks. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/doc-block.css";

Anatomy

Header, body, preview, and code

Doc blocks organize static documentation. Copy, collapse, syntax highlighting, and preview switching are docs-runtime JavaScript responsibilities. 

<article class="doc-block doc-block--surface" data-vds-doc-block>
  <header class="doc-block__header">
    <h2 class="doc-block__title">Example</h2>
    <p class="doc-block__summary">Short explanation.</p>
  </header>
  <div class="doc-block__body">...</div>
</article>

Copy-safe example

Toolbar controls

Toolbar controls are real buttons and need explicit types plus accessible names.

html 
<button type="button" aria-label="Copy code example">Copy</button>

Accessibility

Docs runtime boundaries

CSS exposes visual states for code blocks, toolbars, and collapsed panels. The docs runtime owns state synchronization, copy feedback, focus handling, and syntax token generation.

  • Use real headings for doc block titles.
  • Keep copy and collapse buttons keyboard accessible.
  • Synchronize aria-expanded when code blocks collapse.
  • Do not rely on syntax color alone to explain code meaning.
