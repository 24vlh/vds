Foundation

Typography

Typography styles readable prose, inline semantics, code blocks, lists, figures, prose tables, blockquotes, and footnotes inside a scoped wrapper.

Source truth

Imports and scope

Typography is authored in src/components/typography.css and ships through dist/components/typography.css. It depends on base and primitives. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/typography.css";

Use typography, vds-typography, or data-vds-typography to scope prose rules so component tables and controls are not accidentally restyled.

Copy-safe example

Prose content

The wrapper controls presentation only. The content author still owns heading order, links, alternatives, and table appropriateness. 

<article class="typography">
  <h2>Release notes</h2>
  <p>Use prose for long-form explanation, not operational dashboards.</p>
  <blockquote>Keep status meaning available in text.</blockquote>
  <pre><code>npm install @24vlh/vds</code></pre>
</article>

Boundaries

Prose tables are not data grids

Typography includes basic table styling for editorial content. Use the tables component for dense data, sticky headers, selection, expansion, loading, or numeric helpers.

  • blockquote and pullquote are editorial surfaces, not alerts.
  • badge-inline is inline emphasis, not a status taxonomy.
  • fn-ref and fn-backref need valid targets and return links.
  • Truncation and clamp behavior belongs to utilities or the consuming layout.

Accessibility

Semantics are authored, not styled

Typography CSS cannot choose the correct heading level, explain a figure, or make code meaningful.

  • Use one page title and a logical heading sequence.
  • Add meaningful alt text for informative images.
  • Use captions for prose tables and figures where context matters.
  • Validate theme contrast, code contrast, and forced-colors rendering.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
