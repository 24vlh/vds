Command

Command Surfaces

Command CSS styles palettes, pages, cards, queues, progress rows, activity, empty states, and action lists. Search, routing, active item state, and execution are application-owned.

Source truth

Imports

Command surfaces are authored in src/components/command.css and ship through dist/components/command.css. Dialog-like command palettes also compose with overlays. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/overlays.css";
@import "@24vlh/vds/dist/components/command.css";

Example

Command palette

Use dialog semantics for modal command palettes and listbox semantics only when keyboard behavior and active item state are implemented.

Runtime

Consumer-owned behavior

CSS does not filter commands, execute actions, route pages, move focus, or announce no-results.

  • Keep command--open, mount state, focus trap, and focus return synchronized.
  • Choose either aria-activedescendant or roving focus for active items.
  • Announce no-results and long-running command progress when the app changes state.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
