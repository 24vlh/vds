Overlays

Overlays style backdrops, modals, drawers, inline overlays, loading states, mobile sheet/fullscreen variants, scroll-lock hooks, and stacking levels. Dialog behavior is application-owned.

Source truth

Imports and metadata gap

Overlays are authored in src/components/overlays.css and ship through dist/components/overlays.css. Generated metadata is sparse and remains infrastructure follow-up. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/overlays.css";

Accessibility

Dialog contract

Use role="dialog", aria-modal, and a label when the overlay behaves like a modal. CSS does not enforce those semantics.

  • Synchronize modal--active, aria-hidden, and mounted state.
  • Use body.modal-open only when code actually prevents background scroll.
  • Nested confirmations need an explicit policy for stacking and focus return.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
