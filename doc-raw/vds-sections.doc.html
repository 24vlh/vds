Foundation

Sections System

Sections provide page-level rhythm, widths, bands, splits, grids, insets, and responsive composition. They do not create semantic landmarks or decide content hierarchy.

Source truth

Imports and dependencies

Sections are authored in src/components/sections.css and ship through dist/components/sections.css. They expect base, primitives, and layout layers. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/sections.css";

Anatomy

Root, inner, and header

A section usually combines a root, constrained inner wrapper, optional header, and content stack or grid. 

<section class="section section--surface">
  <div class="section__inner">
    <header class="section__header">
      <p class="section__eyebrow">Operations</p>
      <h2 class="section__title">Queue health</h2>
      <p class="section__subtitle">Current routing and review pressure.</p>
    </header>
    <div class="section__grid-3">...</div>
  </div>
</section>

Variants

Rhythm and layout controls

Section variants control density, width, visual bands, split layout, and per-edge padding.

Density: section--xs, section--sm, section--lg, section--xl.
Surfaces: section--surface, section--subtle, section--alt, section--brand.
Layout: section--split, section--split-reverse, section--inset, grids, stacks, and inline groups.

Accessibility

Content order remains the contract

Section CSS can visually reflow content. It does not reorder the DOM, create labels, or assign landmarks.

  • Choose real headings for the document outline.
  • Use aria-labelledby only when a section needs an explicit accessible name.
  • Keep split and reverse layouts readable in source order.
  • Check surface variants against theme contrast and forced-colors behavior.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
