Loading

Skeleton

Skeleton CSS styles loading placeholders, shimmer/static behavior, lines, avatars, blocks, cards, rows, items, stacks, inline compositions, sizes, shapes, and aspect ratios.

Source truth

Imports

Skeleton is authored in src/components/skeleton.css and ships through dist/components/skeleton.css. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/skeleton.css";

Example

Loading card

Mark the loading region busy and treat skeleton shapes as decorative when the region already has a loading label. 

<section class="skeleton-card" aria-busy="true" aria-live="polite" aria-label="Project card loading">
  <div class="skeleton skeleton-line skeleton-line--medium" aria-hidden="true"></div>
</section>

Accessibility

Loading lifecycle

CSS does not fetch data, swap loaded content, suppress focus, or announce completion.

  • Keep skeleton dimensions close to loaded content to reduce layout shift.
  • Use skeleton--static or reduced-motion behavior when shimmer is inappropriate.
  • Application code owns loading state, replacement, announcements, and focusability.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
