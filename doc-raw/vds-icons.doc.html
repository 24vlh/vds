Foundation

Icons System

Icons provide inline SVG styling, mask glyph classes, sizes, loaders, containers, badges, color helpers, and integration hooks. Icon meaning and accessible names are consumer-owned.

Source truth

Imports and metadata gap

Icons are authored in src/components/icons.css and ship through dist/components/icons.css. Generated docs metadata currently has incomplete source_css evidence, which remains infrastructure follow-up. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/icons.css";

Contract

Glyphs, containers, loaders

The CSS supplies visual glyphs and helpers. It does not decide which icon is correct for a task.

Decorative icons should use aria-hidden="true". Icon-only controls need an accessible name on the control itself.

Copy-safe example

Icon-only button

The icon is decorative inside the button. The button name comes from aria-label. 

<button type="button" aria-label="Refresh results">
  <span class="icon icon--refresh" aria-hidden="true"></span>
</button>

Accessibility

Do not rely on glyph or color alone

Pair semantic icons with visible text, status labels, or accessible names. Loader icons do not announce loading state by themselves.

  • Use currentColor behavior intentionally with surrounding text color.
  • Give icon-only buttons names such as "Close dialog" or "Refresh results".
  • Pair icon--danger, icon--warning, and icon--success with text.
  • Consumer code owns loading announcements, status text, and button/control semantics.
