Shared guidance

Accessibility

VDS is CSS-first. The library supplies source-backed visual hooks; consumers own semantic HTML, accessible names, keyboard behavior, focus management, live announcements, and ARIA synchronization.

Source truth

Package surfaces and source evidence

Accessibility examples compose authored CSS under src/ and package-facing imports under dist/. Source CSS remains the behavior contract when examples drift. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/buttons.css";
@import "@24vlh/vds/dist/components/forms.css";
@import "@24vlh/vds/dist/components/feedback.css";

Example

Label, description, state, and action

Prefer native controls before ARIA. Use ARIA to connect names, descriptions, and state that the application actually manages.

Runtime ownership

What application code must own

CSS cannot move focus, validate data, trap focus, announce status, or choose accessible text.

  • Use native HTML semantics before adding ARIA roles.
  • Give icon-only, dismiss, copy, remove, and navigation controls accessible names.
  • Synchronize aria-current, aria-selected, aria-expanded, aria-invalid, aria-busy, and disabled state with real behavior.
  • Use live regions only for meaningful status changes, not for purely visual restyling.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
