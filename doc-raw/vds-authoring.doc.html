Docs foundation

Authoring Layer

Authoring CSS styles Markdown-like prose, admonitions, callouts, heading anchors, footnotes, inline markers, and prose grids inside documentation content.

Source truth

Imports and scope

Authoring is authored in src/components/authoring.css and ships through dist/components/authoring.css. It is for docs/prose content, not app runtime widgets. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/authoring.css";
@import "@24vlh/vds/dist/components/doc-block.css";

Contract

Markdown-style surfaces

Authoring styles generated or handwritten documentation fragments. It does not generate headings, IDs, anchors, copy buttons, or footnote targets.

Tip

Use admonitions for explanatory documentation, not product alerts.

Use feedback components for runtime alerts and status messages in an application.

Copy-safe example

Heading anchor and footnote

Generated-site code owns IDs, anchor URLs, collision handling, and footnote back references. 

<article class="authoring">
  <h2 id="setup">
    Setup
    <a class="heading-anchor" href="#setup" aria-label="Link to setup section">#</a>
  </h2>
  <p>Cache dependencies between documentation builds.</p>
</article>

Accessibility

Generated content still needs semantics

Authoring CSS cannot repair a broken heading outline, invalid anchor target, missing footnote backref, or color-only warning.

  • Use one page title and stable heading IDs.
  • Give heading anchors names such as "Link to setup section".
  • Pair warning and danger callouts with clear text.
  • Keep authoring, typography, and doc-block responsibilities separate.
