Toasts

Toasts style floating stacks, inline notifications, semantic variants, lifecycle classes, actions, close buttons, and progress timers. Notification lifecycle is application-owned.

Source truth

Imports

Toasts are authored in src/components/toasts.css and ship through dist/components/toasts.css. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/toasts.css";

Example

Live notification

Place stacks in a live-region container. The app owns queueing, timers, pause policy, focus, Escape, and dismissal.

<div class="toast-stack" aria-live="polite" aria-label="Notifications">

Accessibility

Lifecycle ownership

CSS animates and displays progress hooks; it does not schedule auto-dismiss or announce changes.

  • Use role="status" for non-critical notifications and role="alert" sparingly.
  • Keep progress timers synchronized with real dismissal timers.
  • Do not rely on semantic color alone; include readable title/message text.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
