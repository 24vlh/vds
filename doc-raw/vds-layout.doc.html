Foundation

Layout System

Layout CSS provides containers, content regions, sections, grids, sidebars, and split patterns. It controls geometry only; landmarks, headings, routing, and reading order remain application-owned.

Source truth

Authoring and package surfaces

Layout is authored in src/layout.css. It is package-facing through dist/core.css and dist/vds.css. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/sections.css";

Use layout.css primitives for page geometry and sections.css when you need section-level rhythm, bands, split layouts, or inset surfaces.

Contract

Core layout primitives

These selectors are safe for app shells, docs pages, dashboards, and marketing-style content areas.

Containers: container, container-wide, container-narrow.
Grids: layout-grid-2 through layout-grid-6.
Regions: content-header, content-body, content-footer.

Copy-safe example

A semantic page shell

Layout classes do not create landmarks. Use native elements for the page structure and apply VDS classes for spacing and responsive behavior. 

<main class="page-content">
  <section class="section">
    <div class="container content-body">
      <h2>Workspace overview</h2>
      <p>Place the actual product content here.</p>
    </div>
  </section>
</main>

Responsive behavior

Collapse is visual, not semantic

Grid, sidebar, and split helpers collapse at their source-defined breakpoints. The DOM order still controls reading order, focus order, and screen reader order.

  • Put the primary content first unless the product has a stronger semantic reason.
  • Use headings and landmarks to describe regions.
  • Keep overflow and sticky behavior tested on narrow screens.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
