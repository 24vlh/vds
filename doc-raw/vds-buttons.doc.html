Buttons

Buttons style native buttons and button-like links. CSS owns visual variants, sizes, icon layout, loading, selected, disabled, and focus states; the application owns actions, routing, and state sync.

Source truth

Imports and dependencies

Buttons are authored in src/components/buttons.css and ship through dist/components/buttons.css. Icon button examples also need icons.css. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/buttons.css";
@import "@24vlh/vds/dist/components/icons.css";

Examples

Actions and links

Use real buttons for in-page actions and links for navigation. Links styled as buttons still route like links and use aria-disabled plus application guards when unavailable.

<button class="button button--primary" type="button">Save changes</button>
<a class="button button--link" href="/docs/buttons/example">View details</a>
<button class="button button--icon" type="button" aria-label="More actions">
  <span class="button__icon icon icon--more-vertical" aria-hidden="true"></span>
</button>

Accessibility

Runtime ownership

CSS does not run an action, prevent navigation, toggle pressed state, or announce loading.

  • Add type="button" unless a form submit/reset is intended.
  • Use aria-label for icon-only controls.
  • Synchronize aria-pressed, aria-busy, and disabled state in application code.
  • Do not rely on color-only variants for destructive or successful meaning.
