Actions

Action Bar

Action bars group contextual commands for selections, bulk actions, sticky footers, and compact toolbars. CSS owns layout and disabled styling; the app owns selection counts and actions.

Source truth

Imports and metadata gap

Action bars are authored in src/components/action-bar.css and ship through dist/components/action-bar.css. Generated metadata currently has incomplete source_css evidence. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/action-bar.css";
@import "@24vlh/vds/dist/components/buttons.css";

Example

Selection actions

Use role="toolbar" only when keyboard toolbar behavior is implemented by the app.

3 selected Bulk actions affect checked rows. 
<div class="action-bar" role="toolbar" aria-label="Selected row actions">
  <strong class="action-bar__count">3 selected</strong>
  <button class="button button--outline" type="button">Archive</button>
  <button class="action-bar__dismiss" type="button" aria-label="Clear selection">Clear</button>
</div>

Accessibility

Consumer-owned state

CSS cannot count selections, dismiss a bar, undo actions, or implement roving focus.

  • Keep selection counts updated in the DOM and consider a polite live region.
  • Use aria-disabled="true" on the bar only when the entire command set is unavailable.
  • Use action-bar--stacked, action-bar--sticky, and action-bar--floating only for visual placement.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
