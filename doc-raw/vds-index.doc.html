VDS 1.0.0 Start Guide

VDS is a CSS-first design system. The package-facing surface is checked-in CSS under dist/; JavaScript behavior belongs to the consuming app or to the docs shell demos.

Install

Package surfaces

Consumers install @24vlh/vds and import package-facing files from dist/. Source files under src/ are authoring truth in this repo. 

npm install @24vlh/vds

@import "@24vlh/vds/dist/vds.css";
@import "@24vlh/vds/dist/themes/graphite.css";

Use dist/vds.css for the full bundle. Use dist/core.css for base, primitives, and layout without component files. Themes are loaded separately from both.

Loading model

Component-level imports

Direct component CSS paths are compatibility-sensitive for 1.0.0. Do not assume an exports map until release infrastructure explicitly adds one. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/buttons.css";
@import "@24vlh/vds/dist/components/forms.css";
@import "@24vlh/vds/dist/themes/slate.css";

Standalone identity CSS is the exception: import dist/identity.css when a page needs only the logo system.

Docs model

Raw-first hybrid documentation

The current docs shell loads handwritten raw HTML fragments. Generated metadata is evidence and index output, not the hand-edited source.

  • doc-raw/*.doc.html is canonical for the 1.0.0 rewrite cycle.
  • index.html and js/doc-loader.js load fragments into the docs shell.
  • @24vlh/agents/docs_vds may drift until infrastructure owns regeneration.
  • When docs disagree with source CSS, source CSS wins and the mismatch becomes backlog work.

Release status

What the 1.0.0 docs must prove

The docs should help a user install VDS, choose the right CSS surface, copy safe examples, and understand which runtime behavior they own.

  • Examples use source-backed selectors and current package paths.
  • Icon-only controls, logo links, and copy controls require accessible names.
  • Interactive examples name JavaScript, focus, keyboard, routing, and ARIA responsibilities.
  • Migration notes will be finalized with the release coordination sessions.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
