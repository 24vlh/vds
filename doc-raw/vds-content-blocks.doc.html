Content Blocks

Content block CSS styles cards, callouts, features, facts, highlights, empty states, media blocks, KPIs, tags, chips, and split layouts. CSS owns composition; product code owns meaning and actions.

Source truth

Imports and package surface

Content blocks are authored in src/components/content-blocks.css and ship through dist/components/content-blocks.css. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/content-blocks.css";

Accessibility

Composition ownership

CSS cannot choose heading levels, decide link targets, validate metrics, or announce updates.

  • Keep heading levels consistent with the surrounding page.
  • Provide alt text for meaningful media or mark decorative media with empty alt.
  • Do not rely on tag, chip, or highlight color alone.
  • Application code owns selection, routing, metrics accuracy, and action behavior.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
