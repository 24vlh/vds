Release

Migration

Migration guidance tracks the move from the current 0.3.8 package toward VDS 1.0.0. Breaking selector, token, import, and example changes must be explicit.

Source truth

What must be reviewed

Review authored CSS under src/, package-facing CSS under dist/, raw docs, generated metadata drift, and consumer import paths before release notes are final. 

@import "@24vlh/vds/dist/vds.css";
@import "@24vlh/vds/dist/themes/graphite.css";
@import "@24vlh/vds/dist/components/buttons.css";

Workflow

Migration note checklist

Preserve where cheap, alias where useful, and remove only when release notes explain the replacement.

  1. List selector, token, import, and docs-example changes.
  2. Record whether each change is preserved, aliased, deprecated, or removed.
  3. Verify package-facing dist output after the approved infrastructure session refreshes it.
  4. Publish known limitations with the changelog and release notes.
0.3.8 usage: @import "@24vlh/vds/dist/components/forms.css";
1.0.0 action: keep direct dist component import unless release notes say otherwise.

Accessibility

Runtime behavior must not migrate silently

Application-owned JavaScript, ARIA synchronization, focus, keyboard, routing, validation, and live announcements remain consumer responsibilities unless a release note says otherwise.

  • Document any changed state selector or ARIA alias.
  • Document any changed theme token that affects contrast or focus visibility.
  • Document any changed example that affects button type, labels, roles, or live-region behavior.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
