Foundation

Utilities

Utilities provide low-level layout, spacing, sizing, typography, visibility, overflow, position, and accessibility helpers. They do not create component behavior or semantics.

Source truth

Imports and package path

Utilities are authored in src/components/utilities.css and ship through dist/components/utilities.css. They expect core tokens and base defaults. 

@import "@24vlh/vds/dist/core.css";
@import "@24vlh/vds/dist/components/utilities.css";

Contract

Use utilities to compose, not to hide product decisions

Utilities are intentionally broad. Prefer a component selector when the UI surface has a named contract, state model, or accessibility requirements.

Layout: flex, grid, cluster, stack.
Spacing: gap-4, p-4, mt-6, gutter-md.
State helpers: hidden, sr-only, cursor-not-allowed.

Copy-safe example

Small composition

This example composes layout only. Button behavior, accessible labels, and action handling remain the consuming application's responsibility. 

<div class="flex items-center justify-between gap-4 p-4 border radius-md">
  <div class="stack gap-1">
    <strong>Pending reviews</strong>
    <span class="text-muted">12 items need attention</span>
  </div>
  <button type="button" aria-label="Open pending reviews">Open</button>
</div>

Accessibility

Utilities do not add meaning

A utility can hide, align, or space content. It cannot supply labels, relationships, live announcements, keyboard behavior, or status meaning.

  • Use sr-only only for text that should remain available to assistive technology.
  • Do not use visual color utilities as the only status signal.
  • Keep responsive variants consistent with DOM and focus order.
  • Large utility pruning is a release policy decision, not a docs rewrite decision.

Validation

Example quality and release checks

Source truth and package-facing imports must stay aligned: authoring evidence lives under src/, while copyable consumer imports use dist/. Validate examples in narrow and wide viewports, active themes, reduced-motion, forced-colors, and high-contrast contexts.

  • Examples must remain source-backed, copy-safe, and realistic enough to adapt.
  • Application code owns runtime JavaScript, ARIA synchronization, focus, keyboard, routing, lifecycle, and announcements.
  • Responsive, theme, motion, and contrast behavior must be checked in the consuming layout.
  • Migration and release notes must record any changed selector, token, import, or example contract.
